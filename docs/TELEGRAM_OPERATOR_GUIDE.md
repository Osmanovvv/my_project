# Операторское меню Telegram

Оператор работает через тот же `@ITagent_bot`, что и клиент. Отдельная группа,
темы и пересылка сообщений в личный аккаунт оператора не используются.
Клиент оставляет заявку и продолжает переписку в своём личном чате с ботом.

## Доступ

Операторский режим открывается только в подтверждённом личном чате. Сервер
одновременно проверяет:

- Telegram user ID находится в `TELEGRAM_OPERATOR_IDS`;
- chat ID совпадает с `TELEGRAM_OPERATOR_CHAT_ID`;
- входящий update и callback относятся к текущему окружению;
- одноразовая кнопка не истекла, не использована повторно и принадлежит этому
  оператору, чату и версии его сессии.

Знание команды `/admin` само по себе не даёт доступа. Чужой пользователь,
чужой chat ID или подделанный callback не получают карточки и историю. Клиент
видит только своё клиентское меню и собственные обращения.

`TELEGRAM_OPERATOR_IDS` — список разрешённых Telegram user ID через запятую.
`TELEGRAM_OPERATOR_CHAT_ID` — подтверждённый chat ID личного чата оператора.
Оба значения задаются на сервере в защищённом env-файле и не публикуются в
клиентских сообщениях, URL или сборке сайта.

## Как работает меню

Команда `/admin` открывает закрытое меню с разделами:

1. **Новые заявки** — обращения в начальном статусе.
2. **Диалоги** — все доступные оператору обращения.
3. **Ожидают ответа** — диалоги, где клиент ждёт оператора.
4. **Непрочитанные** — обращения с новыми сообщениями.
5. **Поиск** — `/search текст` по карточкам обращений.

Карточка обращения показывает номер, имя и username клиента, его Telegram ID,
статус, источник, окружение, связанную заявку сайта и историю. У каждого
действия сохраняются выбранный `conversation`, chat ID и Telegram user ID
получателя.

## Ответ клиенту

Оператор нажимает «Ответить клиенту», пишет черновик, получает предпросмотр и
только потом нажимает «Отправить клиенту». Свободный текст в меню не считается
ответом и не отправляется автоматически. Перед отправкой сервер ещё раз
проверяет, что получатель совпадает с личным чатом выбранного обращения.

После подтверждения сообщение попадает в outbox с фиксированным получателем,
а клиент получает его в своём чате с ботом. Личный аккаунт оператора клиенту
не показывается.

## Хранение Telegram-данных

Telegram-профиль, карточка обращения, сообщения и файлы хранятся не дольше
трёх лет с последней активности. Старые сообщения удаляются автоматически,
неактивные карточки обращений удаляются вместе со связанной историей, а
профиль без обращений удаляется после истечения того же срока.

Служебные сроки короче: Mini App и операторские сессии — до 30 дней, сырые
updates — до 7 дней, события — до 90 дней, outbox — до 30 дней, callbacks и
черновики — до 30 минут. Очистка запускается при старте сервера и затем раз в
сутки.

## Внутренняя заметка

«Добавить заметку» сохраняет текст только в операторской истории. Такая запись
имеет тип `internal_note`, служебное направление и признак видимости
`operator`. Клиентский поток отфильтровывает эти записи, поэтому клиент не
видит заметку в истории и не получает её в Telegram.

## Статусы и режимы

Оператор может изменить статус, закрыть обращение или открыть его снова.
Тестовые и рабочие обращения маркируются окружением `TEST` или `РАБОЧИЙ`.
Переключение в рабочий режим доступно только оператору production-приёмника;
локальный процесс не может отправить рабочую очередь.

## Клиентский режим

Клиентский `/start`, Mini App и deep link открывают только клиентские действия:
новая заявка, свои обращения, история и продолжение диалога. Клиент не получает
операторские кнопки, список чужих обращений, Telegram ID оператора или доступ к
внутренним заметкам.
