## Что строим

Многостраничный сайт IT-Agent. По факту — студия, которая делает сайты в связке с Telegram-ботом и админкой для приёма заявок. «Система обработки заявок» — это то, как мы это упаковываем и продаём, а не отдельный сложный продукт.

## Главный принцип дизайна

**Лёгкость, воздух, минимализм.** Не забиваем экраны. Один блок = одна мысль. Много пустого пространства, спокойная типографика, крупные заголовки, короткий текст. Никаких стен из карточек и «фичей у каждого пикселя».

Ориентир по ощущению: Linear / Vercel / Framer — но темнее и теплее, без generic-фиолетового.

## Визуальное направление

- **База:** графит `oklch(0.16 0.01 260)`, поверхности карточек чуть светлее, тонкие границы `oklch(1 0 0 / 0.06)`.
- **Текст:** тёплый off-white, вторичный — приглушённый серый.
- **Акцент:** тёплый янтарь `oklch(0.78 0.15 65)` — только на CTA, активных состояниях, номерах шагов, статусах в демо. Не заливаем им блоки.
- **Типографика:** Space Grotesk (заголовки) + Inter (body), крупные размеры, широкий leading.
- **Радиусы:** 14–16px. **Тени:** мягкие, почти невидимые. **Анимации:** сдержанные fade/slide на скролле.

Токены — в `src/styles.css` через `@theme inline`, шрифты — `<link>` в root head.

## Структура сайта

Роуты (каждый со своим head):

```
/                    — главная
/services            — что мы делаем (сайт + бот + админка)
/packages            — пакеты
/industries          — для кого
/faq                 — частые вопросы
/contacts            — форма заявки
```

Внутренние подстраницы `/services/*` из ТЗ **не делаем в первой итерации** — они противоречат принципу лёгкости. Всё уместим в `/services` одной страницей.

## Главная — минимальный набор секций

Один экран прокрутки = одна идея. Никаких «10 блоков подряд».

1. **Hero** — крупный заголовок «Сайт, который не теряет заявки», один подзаголовок, один основной CTA + вторичная ссылка. Справа/снизу — лёгкий мокап: три иконки в ряд (Сайт → Telegram → Админка), соединённые тонкой линией с янтарной точкой-сигналом. Всё. Никаких статистик, логотипов клиентов, второго CTA.
2. **Что мы делаем** — три коротких пункта в ряд (Сайт · Бот в Telegram · Админка заявок). По одной строке описания на каждый. Много воздуха.
3. **Демо админки** — один большой аккуратный мокап интерфейса со списком заявок (статус, источник, следующий шаг). Слева — короткий текст «Вот так вы видите заявки». Без вкладок, без второго скриншота.
4. **Обычный сайт vs с админкой** — две колонки, по 3 короткие строки. Без иконок у каждой строки, только тонкий разделитель.
5. **Пакеты** — три карточки (Старт / **Бизнес** выделен рамкой в янтаре / Система). В каждой: название, одна строка «кому», 3–4 пункта, цена или «от N», CTA.
6. **Спокойный старт** — одна строка-обещание + 3 коротких пункта («не нужно ТЗ», «начнём с разбора», «развиваем после запуска»).
7. **CTA-блок с формой** — заголовок, короткая форма (имя, контакт, одна строка про задачу), справа — 3 строки «что будет после». Один экран.
8. **Футер** — минимальный: логотип, три ссылки, контакт.

Итого ~7 смысловых экранов. Не 15.

## Внутренние страницы

- `/services` — три большие секции подряд (Сайт / Бот / Админка), у каждой один мокап и короткий текст. В конце — CTA.
- `/packages` — те же три пакета что на главной, но с расширенными деталями (срок, что на выходе, когда не нужен).
- `/industries` — 6 сценариев в чистой сетке 2×3 или 3×2: ниша → задача → решение. Одинаковый ритм, без визуального шума.
- `/faq` — простой accordion, 8–10 вопросов, ничего больше.
- `/contacts` — та же форма с главной, крупнее, + телефон/Telegram/email.

## Что не делаем (стоп-лист лёгкости)

- иконка у каждого буллита;
- «доверительные» блоки с логотипами/цифрами без пруфов;
- параллаксы, gradient meshes, декоративные размытые круги повсюду;
- 4+ CTA на экране;
- длинные абзацы (максимум 2–3 строки);
- одинаковые карточки рядами 3×N без вариации ритма;
- модалки, тултипы, «умные» интерактивы, которые не нужны для продажи.

## Технически

- TanStack Start, Tailwind v4, shadcn — как в шаблоне.
- Токены в `src/styles.css` через `@theme inline`.
- Шрифты через `<link>` в `__root.tsx`.
- Каждый route — свой файл с уникальным `head()` (title/description/og).
- Форма — клиентский мок с toast «спасибо, свяжемся», без бэка. Бэк (Lovable Cloud + Telegram-уведомления) — отдельным этапом после утверждения дизайна.
- Демо-админки — статичный HTML/CSS, не приложение.
- Адаптив: 360 / 768 / desktop.

## В первой итерации

Строю **главную + шапку/футер + базовую дизайн-систему + пустые страницы всех роутов** (с правильным head, чтобы навигация работала). Внутренние страницы наполняем следующей итерацией — так проще всего оценить визуальный тон и подкрутить, пока не разъехалось на 6 страниц.
