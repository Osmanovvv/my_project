# Развёртывание

## Сборка

```bash
NITRO_PRESET=node-server bun run build
```

Получается `.output/server/index.mjs` — самодостаточный Node-сервер.
Запуск: `PORT=3000 node .output/server/index.mjs`

По умолчанию (без `NITRO_PRESET`) собирается Cloudflare Worker — он не
запустится на обычном хостинге.

**Если сборка падает с `UNLOADABLE_DEPENDENCY` и «не удаётся найти путь»** —
это устаревший кеш, а не ошибка в коде:

```bash
rm -rf .output node_modules/.nitro node_modules/.vite
```

## Обязательно: сжатие на веб-сервере

Сервер Nitro отдаёт файлы **без gzip**. Если поставить его голым, страница
будет грузиться втрое дольше. Замерено на профиле мобильного Lighthouse:

|                  | без сжатия | со сжатием |
| ---------------- | ---------- | ---------- |
| Performance      | 62         | 84         |
| Первая отрисовка | 5.8 с      | 3.2 с      |
| CSS по сети      | 91 КБ      | 13.6 КБ    |

Перед приложением обязан стоять nginx со сжатием. Минимальный конфиг:

```nginx
gzip on;
gzip_types text/plain text/css application/javascript application/json image/svg+xml;
gzip_min_length 1024;
gzip_comp_level 6;

location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-Host $host;
}
```

`X-Forwarded-Host` и `X-Forwarded-Proto` не декоративные: из них
`originFromRequest` (`src/lib/site-urls.ts`) собирает адреса для
`sitemap.xml` и `robots.txt`. Без них там окажется `localhost`.

## Переменные окружения

| Переменная           | Зачем                                        | Без неё                                 |
| -------------------- | -------------------------------------------- | --------------------------------------- |
| `DATA_DIR`           | где лежат база и картинки                    | берётся `.data` рядом с процессом       |
| `ADMIN_PASSWORD`     | первый пароль в админку                      | войти нельзя                            |
| `TELEGRAM_BOT_TOKEN` | уведомления о заявках                        | заявка сохранится, уведомления не будет |
| `TELEGRAM_CHAT_ID`   | куда слать уведомления                       | то же                                   |
| `VITE_SITE_URL`      | адрес сайта для canonical, og:image, sitemap | берётся `https://itagent.ru`            |

`VITE_SITE_URL` вшивается в бандл **на этапе сборки** — задавать её нужно
до `bun run build`, а не при запуске сервера.

`ADMIN_PASSWORD` должен быть **не короче 8 символов** — короткий сервер
не примет и напишет об этом в лог при запуске. Читается он **только при
первом запуске**, пока пароль не задан:
дальше он хранится хешем в базе, и переменную можно убрать. Повторный запуск
с той же переменной ничего не перезаписывает — иначе смена пароля в админке
откатывалась бы при каждом перезапуске.

## Каталог данных

`DATA_DIR` — единственное место, где живёт всё, что нельзя потерять:

```
$DATA_DIR/
  content.db     ← заявки, кейсы, настройки
  media/         ← загруженные фотографии
```

Он намеренно **вне** каталога приложения: `.output` стирается при каждой
сборке, а `public/` раздаётся статикой целиком — база, лежащая там, утекла бы
в интернет. Задайте `DATA_DIR` явно, например `/var/lib/itagent`, и убедитесь,
что каталог доступен на запись пользователю, от которого работает процесс.

## Резервные копии

База — один файл, картинки — одна папка. Копировать базу простым `cp` нельзя:
она может оказаться в середине записи. Целостный снимок делает сама SQLite:

```bash
sqlite3 /var/lib/itagent/content.db "VACUUM INTO '/tmp/content-backup.db'"
tar czf backup-$(date +%F).tar.gz -C /tmp content-backup.db -C /var/lib/itagent media
```

Проверьте восстановление хотя бы один раз: копия, которую ни разу
не разворачивали, — это не резервная копия, а надежда на неё.

## Отдача картинок

Загруженные фотографии раздаёт само приложение по адресу `/media/…`, и это
работает без дополнительной настройки — намеренно, чтобы забытая строка
в конфиге не ломала картинки на сайте. На боевом сервере их можно отдавать
через nginx напрямую, будет быстрее:

```nginx
location /media/ {
    alias /var/lib/itagent/media/;
    add_header Cache-Control "public, max-age=31536000, immutable";
}
```

Имя файла содержит хеш содержимого, поэтому кеш можно держать вечно:
изменилась картинка — изменился адрес.

## Админка

Доступна по `/admin`, закрыта паролем. В `robots.txt` стоит `Disallow`,
на страницах — `noindex`. Но настоящая защита — только пароль, поэтому
**сайт обязан работать по HTTPS**: без него cookie сессии ходит открытым
текстом. Приложение определяет протокол по заголовку `X-Forwarded-Proto`,
который пробрасывает nginx (см. конфиг выше), и только тогда помечает cookie
`Secure`. Если заголовок не пробросить, cookie останется без этой отметки.

## Проверка после деплоя

```bash
curl -I -H "Accept-Encoding: gzip" https://itagent.ru/   # ждём content-encoding: gzip
curl -s https://itagent.ru/sitemap.xml | head -5          # ждём свой домен, не localhost
curl -I https://itagent.ru/admin                          # ждём переход на /admin/login
```

И отправить тестовую заявку через форму. Она должна появиться в админке —
а если настроен Telegram, то и уведомление в чате.
