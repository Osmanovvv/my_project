# Развёртывание

## Сборка

```bash
NITRO_PRESET=node-server bun run build
```

Получается `.output/server/index.mjs` — самодостаточный Node-сервер.
Запуск: `PORT=3000 node .output/server/index.mjs`

По умолчанию (без `NITRO_PRESET`) собирается Cloudflare Worker — он не
запустится на обычном хостинге.

**Если сборка падает с `UNLOADABLE_DEPENDENCY` и «не удаётся найти путь»** —
это устаревший кеш, а не ошибка в коде:

```bash
rm -rf .output node_modules/.nitro node_modules/.vite
```

## Обязательно: сжатие на веб-сервере

Сервер Nitro отдаёт файлы **без gzip**. Если поставить его голым, страница
будет грузиться втрое дольше. Замерено на профиле мобильного Lighthouse:

|                  | без сжатия | со сжатием |
| ---------------- | ---------- | ---------- |
| Performance      | 62         | 84         |
| Первая отрисовка | 5.8 с      | 3.2 с      |
| CSS по сети      | 91 КБ      | 13.6 КБ    |

Перед приложением обязан стоять nginx со сжатием. Минимальный конфиг:

```nginx
gzip on;
gzip_types text/plain text/css application/javascript application/json image/svg+xml;
gzip_min_length 1024;
gzip_comp_level 6;

location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
}
```

Ни один из заголовков не декоративный. Из `X-Forwarded-Host` и
`X-Forwarded-Proto` `originFromRequest` (`src/lib/site-urls.ts`) собирает
адреса для `sitemap.xml` и `robots.txt` — без них там окажется
`localhost`. По `X-Forwarded-For` форма ограничивает частоту отправки
(3 заявки в минуту с одного адреса). Без него приложение не видит адресов
вовсе, и лимит становится общим на всех посетителей: четвёртый человек
за минуту получит «слишком много заявок».

## Переменные окружения

| Переменная           | Зачем                                        | Без неё                                 |
| -------------------- | -------------------------------------------- | --------------------------------------- |
| `DATA_DIR`           | где лежат база и картинки                    | берётся `.data` рядом с процессом       |
| `ADMIN_PASSWORD`     | первый пароль в админку                      | войти нельзя                            |
| `TELEGRAM_BOT_TOKEN` | уведомления о заявках                        | заявка сохранится, уведомления не будет |
| `TELEGRAM_CHAT_ID`   | куда слать уведомления                       | то же                                   |
| `VITE_SITE_URL`      | адрес сайта для canonical, og:image, sitemap | берётся `https://itagent.ru`            |

`VITE_SITE_URL` вшивается в бандл **на этапе сборки** — задавать её нужно
до `bun run build`, а не при запуске сервера.

Файл `.env` в рабочем каталоге процесса **подхватывается** — но только
для тех переменных, которых в окружении ещё нет. Заданное процессу всегда
главнее файла, иначе забытый `.env` тихо переопределял бы настройки systemd.

Забыть переменную всё равно легко, поэтому приложение печатает в лог, что
у него настроено, — при первом запросе после запуска:

```
[настройки] каталог данных: /var/lib/itagent
[настройки] уведомления о заявках: ВЫКЛЮЧЕНЫ — нет TELEGRAM_BOT_TOKEN и TELEGRAM_CHAT_ID
[настройки]            заявки будут сохраняться, но в Telegram ничего не придёт
[настройки] адрес сайта: https://itagent.ru
```

Это первое, на что стоит смотреть после развёртывания. Без такой строки
недонастроенный сервер выглядит полностью рабочим: форма отвечает
«отправлено», заявка ложится в базу, а уведомления не приходят — и узнать
об этом можно только по молчащему чату.

Готовый юнит лежит в `deploy/itagent.service`: пользователь без root,
переменные, автоперезапуск и ограничение прав на запись одним каталогом
данных. Подставить свои значения и скопировать в `/etc/systemd/system/`.

`ADMIN_PASSWORD` должен быть **не короче 8 символов** — короткий сервер
не примет и напишет об этом в лог при запуске. Читается он **только при
первом запуске**, пока пароль не задан:
дальше он хранится хешем в базе, и переменную можно убрать. Повторный запуск
с той же переменной ничего не перезаписывает — иначе смена пароля в админке
откатывалась бы при каждом перезапуске.

## Каталог данных

`DATA_DIR` — единственное место, где живёт всё, что нельзя потерять:

```
$DATA_DIR/
  content.db     ← заявки, кейсы, настройки
  media/         ← загруженные фотографии
```

Он намеренно **вне** каталога приложения: `.output` стирается при каждой
сборке, а `public/` раздаётся статикой целиком — база, лежащая там, утекла бы
в интернет. Задайте `DATA_DIR` явно, например `/var/lib/itagent`, и убедитесь,
что каталог доступен на запись пользователю, от которого работает процесс.

## Резервные копии

База — один файл, картинки — одна папка. Копировать базу простым `cp` нельзя:
она может оказаться в середине записи. Целостный снимок делает сама SQLite —
это и делает `deploy/itagent-backup.sh`, а `deploy/itagent-backup.timer`
запускает его каждую ночь и удаляет копии старше 30 дней. Установка описана
в шапке `deploy/itagent-backup.service`; нужен пакет `sqlite3`.

Руками то же самое:

```bash
sqlite3 /var/lib/itagent/content.db "VACUUM INTO '/tmp/content-backup.db'"
tar czf backup-$(date +%F).tar.gz -C /tmp content-backup.db -C /var/lib/itagent media
```

Проверьте восстановление хотя бы один раз: копия, которую ни разу
не разворачивали, — это не резервная копия, а надежда на неё.

## Обновление версии

Схема базы обновляется сама при первом запуске новой сборки: приложение
сверяет `PRAGMA user_version` и докатывает недостающие миграции. Отдельной
команды запускать не нужно.

Откатиться назад после этого нельзя — старая сборка не знает про новые
колонки. Поэтому снимок базы делается ДО запуска новой версии, а не после:

```bash
sqlite3 /var/lib/itagent/content.db "VACUUM INTO '/tmp/before-update.db'"
systemctl restart itagent
```

Сам сайт при этом не зависит от базы целиком: тексты, цены и мета-теги имеют
значения по умолчанию в коде, и пустая или потерянная база означает лишь то,
что страницы отрисуются исходным содержимым. Потеряются правки владельца,
а не сайт.

## Отдача картинок

Загруженные фотографии раздаёт само приложение по адресу `/media/…`, и это
работает без дополнительной настройки — намеренно, чтобы забытая строка
в конфиге не ломала картинки на сайте. На боевом сервере их можно отдавать
через nginx напрямую, будет быстрее:

```nginx
location /media/ {
    alias /var/lib/itagent/media/;
    add_header Cache-Control "public, max-age=31536000, immutable";
}
```

Имя файла содержит хеш содержимого, поэтому кеш можно держать вечно:
изменилась картинка — изменился адрес.

## Админка

Доступна по `/admin`, закрыта паролем. В `robots.txt` стоит `Disallow`,
на страницах — `noindex`. Но настоящая защита — только пароль, поэтому
**сайт обязан работать по HTTPS**: без него cookie сессии ходит открытым
текстом. Приложение определяет протокол по заголовку `X-Forwarded-Proto`,
который пробрасывает nginx (см. конфиг выше), и только тогда помечает cookie
`Secure`. Если заголовок не пробросить, cookie останется без этой отметки.

## Персональные данные: что должно быть правдой к запуску

Страница `/privacy` описывает, как сайт обращается с данными заявок. Каждое
её утверждение — обещание, и код его либо обеспечивает, либо нет:

| Обещание в политике                      | Чем обеспечено                                                                                                                                                  |
| ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| база на сервере в России                 | **хостинг в РФ** из реестра РКН — выбирается руками, код не проверит                                                                                            |
| соединение по HTTPS                      | nginx + сертификат (см. «Админка»)                                                                                                                              |
| заявки не дольше 3 лет                   | `purgeExpiredLeads` — при каждой новой заявке                                                                                                                   |
| журналы не дольше 30 дней                | logrotate у nginx + `MaxRetentionSec=30day` у journald (ниже)                                                                                                   |
| ежедневная копия, хранится 30 дней       | `deploy/itagent-backup.timer` — см. «Резервные копии»                                                                                                           |
| оператор — конкретное лицо               | админка → Разделы → «Оператор данных»: ФИО, статус, ИНН                                                                                                         |
| куда писать по вопросам данных           | админка → Контакты → **почта обязательна**: без неё документ отсылает на страницу контактов, а отозвать согласие через форму нельзя — она сама требует согласия |
| уведомление в Telegram: состав и адресат | так и есть — `formatLeadMessage`; менять состав — править раздел 4                                                                                              |

Факт согласия пишется в заявку (`consent_at`, `consent_version`) и виден
в её карточке. Редакция документов — `LEGAL_VERSION` в `src/data/legal.ts`;
изменили текст — поменяйте дату.

**До первой заявки** владелец подаёт уведомление в Роскомнадзор об обработке
персональных данных (ч. 1 ст. 22 152-ФЗ) — на pd.rkn.gov.ru. В уведомлении
указывается адрес политики: `https://itagent.ru/privacy`.

**Если появится Яндекс Метрика** или любой другой счётчик — в тот же день
править раздел 4 политики: сейчас там честно написано, что сторонних
счётчиков и cookies для посетителей нет.

**При утечке** (взлом админки, попавшая наружу база, случайно разосланный
файл) — не молчать. Ч. 3.1 ст. 21 152-ФЗ, отсчёт с момента, когда узнали:
в течение 24 часов уведомить Роскомнадзор об инциденте, предполагаемых
причинах и вреде, принятых мерах и контактном лице; в течение 72 часов —
о результатах внутреннего разбора и виновных (если есть). Параллельно
сменить пароль админки и перевыпустить токен бота.

**При отзыве согласия** (человек написал «удалите мои данные»): открыть
заявку в админке и удалить её — это затирает запись в базе; затем удалить
уведомление о ней из чата Telegram руками — туда автоматика не дотянется.
Срок — 30 дней с момента получения письма, обещано в разделе 5 политики.
Из резервных копий запись уйдёт сама через 30 дней вместе с копией.

**Telegram — это передача за границу.** Уведомление с именем и контактом
уходит на серверы Telegram, и политика честно об этом говорит. По ч. 3
ст. 12 152-ФЗ трансграничная передача требует отдельного уведомления
в Роскомнадзор до её начала; относится ли это к уведомлениям бота —
официального разъяснения нет (см. отчёт проверки). Два безопасных пути:
подать уведомление о трансграничной передаче вместе с основным, либо
слать в Telegram только номер заявки без данных. Решение — за владельцем.

Пример logrotate для nginx (`/etc/logrotate.d/nginx`, на Ubuntu он уже
такой — проверить `rotate`):

```
/var/log/nginx/*.log {
    daily
    rotate 14
    compress
    missingok
    notifempty
}
```

Журнал приложения пишет systemd → journald, у которого по умолчанию срока
нет. В `/etc/systemd/journald.conf`:

```
[Journal]
MaxRetentionSec=30day
```

и `sudo systemctl restart systemd-journald`. Содержимое заявок в этот
журнал не попадает (только номера), но обещание «не дольше 30 дней»
относится ко всем журналам.

## Проверка после деплоя

```bash
curl -I -H "Accept-Encoding: gzip" https://itagent.ru/   # ждём content-encoding: gzip
curl -s https://itagent.ru/sitemap.xml | head -5          # ждём свой домен, не localhost
curl -I https://itagent.ru/admin                          # ждём переход на /admin/login
```

И отправить тестовую заявку через форму: без галочки согласия кнопка
не нажимается, с ней заявка должна появиться в админке с отметкой
о согласии — а если настроен Telegram, то и уведомление в чате.
Открыть `/privacy` и убедиться, что оператором назван человек, а не «IT-Agent».
